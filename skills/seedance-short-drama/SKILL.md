# Seedance 短剧生产（兼容别名）

> 新项目请优先使用 `$short-drama-production`。本 Skill 只提供兼容入口，运行时映射到同一套 `ShotPackage`、Asset Binding、Quality Gate 和可恢复 Agent 图；未指定 Profile 时默认 `seedance/seedance-2.0-video`。

## 目标与边界

本 Skill 面向短剧、漫剧和竖屏连续剧的镜头级生产准备：把已经确定的创意、剧本、分镜、资产设定或参考素材，转换成可直接交给 Seedance 的中文视频提示词和生产检查单。

触发条件包括：

- 把短剧分镜、单集剧本或镜头意图写成 Seedance 提示词；
- 把图片、视频、音频素材绑定到首帧、尾帧、人物、场景、运镜、动作、节奏或声音用途；
- 为视频延长、视频编辑、角色/道具替换、多视频融合或图生视频写提示词；
- 检查已有提示词的时长、引用、连续性、动作可行性和安全风险；
- 批量整理一集或一组镜头的生产包。

不承担以下工作：生成或上传媒体、调用供应商 API、从零编写完整剧本、独立设计角色/场景资产、替代分镜或项目终审。需要这些工作的任务应转交给对应的创作、资产、生产或审查 Skill。

## 工作原则

1. **保留戏剧意图。** 不擅自改写人物关系、台词、结局或镜头职责；发现冲突时先标注，再提出最小改动建议。
2. **一个镜头一个主任务。** 一个镜头只承担一个主要动作或情绪转折；把连续动作拆成有明确起止状态的时间段。
3. **引用必须有语义。** 每个 `@` 素材都要说明参考维度；禁止只写“参考 @视频1”。
4. **先确认事实，再使用参数。** Seedance 的输入数量、格式、时长、分辨率和真人限制可能随版本或入口变化。优先采用用户给出的当前界面/版本约束；未知时写“待按当前入口确认”，不要编造硬限制。
5. **可拍摄、可生成、可验收。** 描述可观察的动作、视线、接触关系、镜头路径和声音结果，避免抽象形容词替代行为。
6. **不绕过安全与权利边界。** 不协助规避平台审核，不把真人身份、声音或受版权保护的内容伪装成无授权素材。危险动作、敏感人物和品牌素材必须单独标记风险。

## 输入契约

尽量取得以下信息；缺少的信息只有在会改变镜头职责、人物身份、动作安全或素材绑定时才追问：

- 镜头/场次编号、戏剧目的、预计时长和画幅；
- 起始画面、结束画面、人物身份与当前造型；
- 场景、时间、天气、光线、关键道具及其状态；
- 动作顺序、表演情绪、视线、接触关系和台词；
- 景别、机位、运镜、速度、对焦、轴线与转场要求；
- BGM、环境声、音效、旁白、对白和口型要求；
- 所有输入素材的类型、编号、来源、授权状态和用途；
- 当前 Seedance 版本/入口的限制（若已知）。

若输入不完整，做出最少且可撤销的假设，并在交付开头列出“假设与待确认项”。不要用大量反问阻塞低风险任务。

## 标准交付格式

单镜头至少输出以下内容：

1. **镜头结论**：镜头目的、时长、画幅、模式和一行风险提示。
2. **素材分工表**：`ID / 类型 / 用途 / 必须保留的特征 / 授权或缺口`。未使用的素材明确标记“弃用”，不要强行塞入提示词。
3. **时间轴**：用不重叠且覆盖全时长的区间，例如 `0.0–2.5s`；每段写画面动作、表演和镜头。
4. **最终提示词**：放进一个可复制的代码块，引用 ID 与素材分工表完全一致。
5. **音画与文本约束**：对白、口型、BGM、音效、屏幕文字分别写清楚；关键字幕乱码风险要注明后期叠字建议。
6. **验收清单**：引用完整性、时长和动作数量、连续性、指令冲突、安全/版权风险、待确认项。

批量任务另外输出全局连续性表（角色造型、道具状态、屏幕方向、视线、光线、声音和已锁定首尾帧）以及“镜头间依赖关系”。不要把上一镜头的临时状态遗失在单条提示词里。

## 提示词编写规则

- 开头先定义主体、场景和输出意图，再写动作和镜头；风格词放在后段。
- 用统一的引用格式：`@图片1`、`@视频1`、`@音频1`。若原始素材编号不一致，先建立别名映射，不要在最终提示词中混用 `@图1`、`@图片1`、`@视频`。
- 每个引用写明一个或多个职责，例如“`@视频1` 仅参考跟拍路径和节奏，不复制人物身份、剧情或画面文字”。
- 关键动作写成“谁在何时以什么方向做什么，接触什么，最后停在哪里”；不要只写“自然地表演”“高级感转场”。
- 关键运镜至少说明景别、机位、方向、速度、焦点和结束状态；不得同时要求固定机位与环绕/跟拍等互相冲突的运动。
- 时间段总和必须等于目标时长；每段只安排一个主要动作，给转身、拿取、对话和情绪变化留出可生成的时间。
- 对白使用“角色名 + 原文 + 情绪/语速/音量”；不要为了塞信息把一句台词写成段落。没有可靠口型要求时，建议旁白或后期配音。
- 音频分为 BGM、环境声、动作音效、对白/旁白，并写出相互关系（例如对白时 BGM 降低）。避免要求复制无授权的完整商业录音。
- 即使没有音乐，也明确写 `BGM：无` 或 `BGM：待定`；不要让缺省音频层在批量制作时变成隐性假设。
- 屏幕文字必须给出准确字串、出现时刻和位置；重要信息默认建议后期叠字，不把生成模型的文字清晰度当作硬保证。
- 视频延长/编辑必须区分“保留内容”和“改动内容”，并写明新增段的起始状态；不要只写“延长 5 秒”或“把人物换掉”。
- 关键剧情信息缺失时使用显式占位符（例如 `男主录音原文：[待提供]`），并将“不可验收”列为警告或阻塞项；不要让模型用泛化情绪替代因果信息。
- 允许使用无参考的通用道具，但必须登记为“外观假设”；会影响特写、剧情或连续性的道具优先要求参考图。

## 生产前检查

交付前逐项检查：

- 所有 `@` ID 都存在、用途明确、类型匹配，且无悬空引用；
- 素材总量、格式、大小、时长和输出档位按当前入口核对，未知项标为待确认；
- 时间轴无重叠、无空段，复杂度与时长匹配；
- 人物脸、发型、服装、道具、左右手、屏幕方向、视线、光线和声音状态与前后镜头一致；
- 运镜、景别、转场、动作和对白没有互相冲突；
- 危险动作、真人肖像/声音、未成年人、隐私、品牌和版权素材已标注并有替代方案；
- 关键文字、对白、口型或剧情信息不依赖不可控的生成细节；
- 交付中明确列出未决问题，不用“完全保证”“百分百还原”等不可验收措辞。

需要做机械检查时，运行 `scripts/validate_prompt.py`；它只检查结构性问题，不替代人工观看生成结果。
