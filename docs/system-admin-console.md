# LumenX 系统管理员后台手册

本文面向平台唯一系统管理员。后台是平台运营、安全、内容审查和财务控制面，不是普通用户的创作工作区；不提供管理员代登录、用户资产修改、硬删除或多角色 RBAC。

## 入口与初始化

完整 Compose 启动时，`admin-bootstrap` 在数据库迁移后自动运行。默认本地账号为 `admin`，密码来自 `.env` 的 `LUMENX_BOOTSTRAP_ADMIN_PASSWORD`。管理员只写入 `admin_users`，不会创建 `users`、钱包、工作区或用户资产。生产必须在首次启动前替换密码，并通过私密凭据系统注入。初始化幂等：配置账号已存在时不修改密码，也不创建第二个管理员；本地 Compose 若发现唯一的异名独立管理员，会自动保留其 ID、接管为配置账号、撤销旧会话并记录审计。多个管理员时仍拒绝启动。

管理员初始化完成后，独立的 `registration-mode-bootstrap` 才处理注册策略。本地 Compose 默认激活 `open`，允许手机号和密码直接注册且暂不校验验证码；生产 Compose 默认保持 `disabled`，必须由运营明确激活。两个任务相互独立，因此开放用户注册不会把管理员写入普通用户域。

管理员通过 `#/admin` 登录，服务端认证接口为 `/api/v1/admin/auth/*`，使用独立的 `lumenx_admin_session` 和 `lumenx_admin_csrf` Cookie。首次初始化或显式恢复后的管理员必须先修改密码，后台页面在完成前不会挂载。普通用户访问管理路由时，前端不会挂载后台页面，后端 `/api/v1/admin/*` 也不会接受普通用户会话。后台使用独立导航，不显示创作者工作流侧栏。

管理员遗失密码时，先把 `.env` 中 `LUMENX_BOOTSTRAP_ADMIN_PASSWORD` 改为新的强密码，再显式执行：

```bash
make docker-admin-recover
```

该命令必须带 `--rotate-existing` 才会修改既有密码，会撤销该管理员的全部后台会话并记录审计；普通 `admin-bootstrap` 重跑仍不会覆盖密码。生产环境禁止使用本地默认密码。

本地 Compose 保留卷中若已经存在唯一的独立管理员，但其用户名与 `.env` 的 `LUMENX_BOOTSTRAP_ADMIN_USERNAME` 不同，普通 `make docker-up` 会在迁移后自动把该唯一身份收敛为配置账号。该自动行为由仅在 `docker-compose.override.yml` 启用的 `LUMENX_BOOTSTRAP_ADMIN_ADOPT_EXISTING_SOLE=true` 控制；生产和发布配置保持关闭。

非本地环境或需要人工恢复时，确认目标数据库恰好只有一个管理员后执行：

```bash
make docker-admin-adopt
make docker-up
```

`docker-admin-adopt` 会先应用最新迁移，再复用原管理员 ID，修改用户名和密码、激活账号、撤销其全部后台会话并记录审计。它不会创建第二个管理员，也不会创建普通用户、钱包或工作区；数据库中不是恰好一个管理员时会拒绝执行。

## 导航与职责

| 分区 | 用途 |
| --- | --- |
| 运营概览 | 查看限定时间窗口的用户、人工订单、用量、任务和异常汇总 |
| 用户 | 按 ID、账号、状态、注册日期和钱包异常筛选；创建、停用、恢复、撤销会话和签发一次性重置凭据 |
| 充值订单 | 登记线下人工充值、确认到账、取消、部分/全额退款和只读对账 |
| 系统场景 | 创建、编辑、替换封面、排序、启停和软归档平台场景模板 |
| 资源审查 | 只读查看用户工作区、项目、剧本、角色、场景、道具、媒体、AI 任务和账务摘要 |
| 异常队列 | 查看失败/停滞任务、陈旧预扣、订单账本差异和媒体完整性问题 |
| AI 任务、用量 | 按用户、工作区、状态和日期核查任务执行、计量令牌与算力券结算 |
| 算力券调整 | 赠送、补偿和有依据的扣减；不计入付费充值收入 |
| 模型与配置 | 管理数据库中的模型路由、参数边界、换算规则和功能策略版本 |
| 审计事件 | 按操作员、目标用户/工作区、动作、用途和请求关联标识追踪管理行为 |

所有列表采用稳定的时间与 ID 排序，筛选和分页保存在 URL 中。深链接可以用于内部工单，但不得附带手机号、剧本、提示词、签名媒体 URL 或一次性凭据。

## 人工充值订单

人工充值表示管理员已在线下取得付款证据并手工登记。系统不连接支付渠道，也不声明付款已被第三方验证。

1. 创建待确认订单：填写目标用户、人民币金额（精确到分）、算力券数量（精确到百万分之一张）、可选线下凭证号和中文原因。创建不会增加余额。
2. 确认到账：只允许待确认订单。系统在同一事务中锁定订单和钱包，追加完成事件、充值流水和审计记录，再增加用户可用余额。
3. 取消：只允许待确认订单，不改变钱包。已完成订单只能走退款。
4. 退款：只允许已完成或部分退款订单。现金与算力券均不得超过订单剩余可退额；只扣可用余额，绝不消耗 AI 任务预扣余额。
5. 对账：核对订单状态、不可变事件、充值/退款流水和累计金额。对账只生成报告和异常，不自动修复历史。

每次写操作都需要 CSRF、中文原因、当前版本和幂等键。重复请求使用相同幂等键和相同参数时返回原结果；同一幂等键对应不同参数会被拒绝。版本冲突后页面会刷新最新订单，管理员必须重新判断。

退款余额不足时，先确认用户是否有进行中的 AI 任务预扣。不得释放预扣来凑退款，也不得直接改钱包。与用户确认后可等待任务结算或由财务调整退款方案；所有决定写入工单和新的订单事件。错误充值已进入财务历史后，使用订单退款或单独补偿流水，禁止删除订单、事件或账本。

“算力券调整”中的赠送、补偿和扣减与人工充值严格分离：它们没有现金金额，不进入付费订单数或净收入。禁止为了省步骤而用赠送代替已付款充值。

## 系统场景生命周期

新系统场景包含中文名称/描述、分类、标签、提示词、风格、画幅、Schema 版本、排序和可见状态。封面只接受 10MB 以内的有效 PNG、JPEG 或 WebP，存放在私有系统媒体前缀，浏览器只持有短期访问 URL，不持有对象键。

- 停用：从普通用户目录隐藏，既有用户副本继续可用。
- 排序：更新推荐顺序并增加版本，不修改用户副本。
- 归档：软归档并从目录隐藏，不硬删除源记录、媒体或用户副本。
- 用户复制：在当前用户工作区创建独立场景，保存源场景 ID、源版本、完整快照和媒体来源。管理员后续修改、停用或归档不会改写副本。

停用或归档已有引用的场景时，后台显示当前引用数量并要求显式确认。遇到版本冲突先刷新，不覆盖其他管理员操作。

## 用户资源与敏感访问

默认资源列表只返回允许字段：手机号脱敏，不返回剧本正文、完整提示词、原始对象键、供应商密钥、原始诊断或一次性凭据。管理员不能通过资源审查接口修改用户项目、资产或任务。

查看完整剧本、任务提示词或私有媒体前，必须填写包含中文的具体用途。服务端会重新校验目标用户与工作区，在同一事务内写入审计事件；审计写入失败时不返回敏感内容。媒体预览是最长 15 分钟的 inline 短期链接，不提供无限制下载接口。

工单和日志中只能记录用户 ID、工作区 ID、资源 ID 和请求关联标识。禁止粘贴手机号、正文、提示词、对象键、供应商诊断、线下凭证或幂等键。

## CSV 导出与对账

用户、人工订单、用量/账本和 AI 任务导出复用列表筛选，要求不超过 93 天的时间窗口和中文用途。默认最多 10,000 行，超限时缩小日期或用户范围。CSV 使用 UTF-8 BOM，并对以 `= + - @` 开头的单元格加前缀，防止表格公式注入。导出不含用户正文或二进制，并写入审计事件。

人工订单对账报告显示“一致”或“存在差异”，不提供静默修复按钮。发现差异时：

1. 关闭扩展后台写入或至少暂停相关财务操作。
2. 保存订单号、事件 ID、账本 ID、报告 ID 和请求关联标识。
3. 核对钱包当前余额、预扣、生命周期累计值和用户历史。
4. 使用前向代码/迁移修复根因；需要修正余额时追加有审计原因的补偿或扣减流水。
5. 重新运行只读对账，确认新报告一致后恢复写入。

## 部署、迁移与功能熔断

```text
LUMENX_ADMIN_CONSOLE_ENABLED=true
LUMENX_ADMIN_CONSOLE_MUTATIONS_ENABLED=true
LUMENX_ADMIN_RATE_WINDOW_SECONDS=60
LUMENX_ADMIN_MUTATION_LIMIT=120
LUMENX_ADMIN_SENSITIVE_READ_LIMIT=60
LUMENX_ADMIN_EXPORT_LIMIT=20
```

关闭 `LUMENX_ADMIN_CONSOLE_ENABLED` 会停用扩展后台；关闭 `LUMENX_ADMIN_CONSOLE_MUTATIONS_ENABLED` 会保留只读查看并拒绝人工订单、系统场景等写入。管理员写操作、敏感读取和导出分别按管理员与网络来源限流；云端限流服务不可用时拒绝操作。

上线前在隔离 PostgreSQL 执行：

```bash
LUMENX_DATABASE_URL=<管理员连接> .venv/bin/python scripts/verify_postgres_migrations.py
```

验证必须覆盖全新库和旧库升级、单一 Alembic head、既有媒体回填、自增 bigint 主键、零外键、应用角色 `NOSUPERUSER NOBYPASSRLS`、独立 `app.current_admin_id` 与普通用户 RLS、连接池上下文清除、不可变事件触发器和必要索引。

`0017_physical_admin_identity` 会撤销旧共享管理员用户会话、删除 `users.is_platform_admin`，但保留该用户的普通用户数据；迁移不会自动创建或关联独立管理员。迁移后由 `admin-bootstrap` 创建 `admin_users`。`0018_admin_recovery_rls` 仅允许显式系统恢复上下文更新唯一管理员及撤销其会话，不向普通用户或普通管理员请求放宽范围。一旦存在独立管理员、管理员审计或人工充值历史，不允许降级合并身份，只允许前向修复。生产故障时回退应用到仍兼容新表的版本，保留数据库结构和全部财务/审计历史。

## 事故停用

- 财务或账本异常：先设 `LUMENX_ADMIN_CONSOLE_MUTATIONS_ENABLED=false`，保留只读调查和对账。
- 敏感访问异常：设 `LUMENX_ADMIN_CONSOLE_ENABLED=false`，撤销相关管理员会话并检查审计/访问日志。
- 系统场景媒体异常：关闭后台写入，停用受影响场景；不要删除已被用户副本引用的媒体。
- 限流、Redis 或数据库策略异常：云端保持 fail closed，修复依赖后再恢复，不临时绕过管理员校验或 RLS。

恢复前必须完成数据库迁移检查、后端/前端健康检查、管理员登录、普通用户拒绝、订单/账本对账、系统场景复制与敏感读取审计验证。
